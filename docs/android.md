# Android App

The Android app is a [Capacitor](https://capacitorjs.com/) wrapper of the React app. The web build is bundled inside the APK, so the app opens and works offline. API and SignalR calls go to the deployed server (`VITE_API_BASE_URL=https://<DOMAIN>`), and the server allows the app's origin `https://localhost` through `CORS_ORIGINS`.

Sign-in uses the native Google account picker (`@capacitor-firebase/authentication` with `skipNativeAuth: true`). The plugin returns a Google ID token, and the Firebase web SDK signs in with it. Everything after sign-in (API tokens, sync, real-time updates) is the same code as the web app.

| Item | Value |
|------|-------|
| Application ID | `com.lihtee.quests` |
| Capacitor config | [frontend/capacitor.config.ts](../frontend/capacitor.config.ts) |
| Android project | [frontend/android/](../frontend/android/) (generated by `cap add android`, committed) |
| CI job | `android` in [.github/workflows/ci.yml](../.github/workflows/ci.yml), runs on pushes to `main` |
| Output | Signed release APK `quests-0.1.<run number>.apk`, uploaded as a workflow artifact |

## One-Time Setup

### 1. Create the release keystore

Keep the keystore and its passwords safe. An APK signed with a different key can't update the installed app.

```bash
keytool -genkeypair -v -keystore quests-release.jks -alias quests \
  -keyalg RSA -keysize 2048 -validity 10000
```

Get its fingerprints:

```bash
keytool -list -v -keystore quests-release.jks -alias quests
```

Copy the `SHA1` and `SHA256` lines.

### 2. Register the Android app in Firebase

1. Firebase console → Project settings → Your apps → **Add app** → Android.
2. Package name: `com.lihtee.quests`.
3. Add the release SHA-1 and SHA-256 fingerprints. For local debug builds, also add the debug key's SHA-1 (`keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android`).
4. Download `google-services.json`. Don't commit it; it is git-ignored.

Google must already be enabled under Authentication → Sign-in method (it is, for the web app).

### 3. Add GitHub secrets

Repository → Settings → Secrets and variables → Actions → **Secrets**:

| Name | Value |
|------|-------|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 quests-release.jks` (macOS: `base64 -i quests-release.jks`) |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | Key alias (`quests` in the example above) |
| `ANDROID_KEY_PASSWORD` | Key password |
| `GOOGLE_SERVICES_JSON` | Full contents of `google-services.json` |

The job also uses the existing variables `DOMAIN` and `VITE_FIREBASE_*` (see [deployment](deployment.md#github-configuration)). If a secret is empty, the job fails with an error that names it.

### 4. Allow the app's origin on the server

The production default `CORS_ORIGINS=https://localhost` already covers the app. Nothing to do unless you changed it (see [deployment](deployment.md)).

## What the CI Job Does

1. `npm ci`, then writes `frontend/android/app/google-services.json` and the decoded keystore (in `$RUNNER_TEMP`, mode 600).
2. `npm run build:android`: type check, `vite build --mode android` with `VITE_API_BASE_URL=https://<DOMAIN>`, then `cap sync android`.
3. `./gradlew assembleRelease -PversionCode=<run number> -PversionName=0.1.<run number>` with the signing env.
4. Uploads `quests-0.1.<run number>.apk`. The job fails if no signed APK was produced.

## Install the APK

1. GitHub → Actions → the latest run on `main` → **Artifacts** → download `quests-0.1.<n>.apk` (a zip with the APK inside).
2. Copy the APK to the phone and open it. Allow installs from unknown sources for the file manager or browser when asked.
3. Newer APKs install over the old one and keep the local data, because they are signed with the same key and have a higher version code.

## Local Build

You need Android Studio (Android SDK) and Java 21, in addition to the [prerequisites](../README.md#prerequisites).

1. Put `google-services.json` in `frontend/android/app/`.
2. Create `frontend/.env.android.local` (git-ignored) with the Firebase web values from `.env.local` and the server URL:

   ```bash
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_APP_ID=...
   VITE_API_BASE_URL=https://<DOMAIN>
   ```

3. Build and sync:

   ```bash
   cd frontend
   npm run build:android
   ```

   `cap sync` loads `capacitor.config.ts`, which needs Node.js 23.6+ (Node 24 recommended). On Node 22.6+ run it with `NODE_OPTIONS=--experimental-strip-types`.

4. Open `frontend/android` in Android Studio and run it on a device, or build a debug APK with `./gradlew assembleDebug` (in `frontend/android`).

Android builds always use the deployed server. Running against a local backend on the device isn't set up.

`assembleRelease` without `ANDROID_KEYSTORE_PATH` builds an unsigned APK. Gradle prints `Quests: release signing configured: yes/no` with the version code and name.

## Manual Test Checklist

- [ ] Sign in on the phone with an allowlisted Google account.
- [ ] Turn on airplane mode, create a task, turn airplane mode off: the task appears on the web.
- [ ] Edit a task on the web while the app is open: the phone updates within seconds.
- [ ] Go offline, kill the app, reopen it: the tasks are still there.
- [ ] Sign out, then sign in again: the account picker shows.

## Troubleshooting

| Symptom | Cause and fix |
|---------|---------------|
| Sign-in fails with `DEVELOPER_ERROR` or code 10 | The signing key's SHA-1 is missing in the Firebase Android app. Add it, download `google-services.json` again, and update the secret. |
| Sign-in fails with "Google sign-in returned no ID token" | Check that the APK was built with the `google-services.json` of this Firebase project (it supplies the web client ID the plugin requests the token for). |
| Signed in, but tasks don't load (CORS errors in `chrome://inspect` → WebView console) | `CORS_ORIGINS` on the server doesn't include `https://localhost`. |
| Requests go to `https://localhost/api/...` | The APK was built without `VITE_API_BASE_URL`. |
| Job fails "Secret ... is empty" | Add the named secret (see [Add GitHub secrets](#3-add-github-secrets)). |
